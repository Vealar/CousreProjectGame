# «Ночные сны» — 2D run and gun

Командный учебный проект, разработанный в рамках курсовой работы образовательной программы «Программная инженерия» ФКН НИУ ВШЭ.

«Ночные сны» — однопользовательская 2D-игра жанра **run and gun** с акцентом на сражения с боссами, платформинг и постепенное открытие новых игровых возможностей.

Ниже приведено краткое описание проекта и моей части работы. Более подробная информация о требованиях, архитектуре, игровых механиках и технических решениях находится в программной документации проекта.

**Исходный код и материалы проекта:**  
https://github.com/Vealar/CousreProjectGame/

## О проекте

Основной игровой процесс строится вокруг последовательного прохождения уровней и сражений с уникальными боссами.

Игрок управляет персонажем, перемещается по платформам, использует различные виды оружия и способности и постепенно получает новые возможности по мере прохождения.

Визуальная и сюжетная стилистика проекта построена вокруг темы сновидений: разные части игры отличаются атмосферой и оформлением.

В рамках командного проекта требовалось реализовать:

- основные игровые окна;
- систему сохранений;
- карту;
- настройки;
- статистику и достижения;
- управление главным героем;
- несколько типов оружия и способностей;
- обычных противников;
- набор боссов с различными фазами и механиками атак;
- игровые объекты и окружение.

Также в рамках курсовой работы подготавливался полный комплект программной документации.

## Моя часть работы

Проект выполнялся командой из **двух человек**.

В моей части проекта основное внимание было сосредоточено на игровой логике. Я занимался разработкой:

- передвижения и состояний главного героя;
- системы здоровья и получения урона;
- оружия;
- поведения боссов;
- дополнительных противников;
- опасных и интерактивных объектов уровня;
- системы достижений;
- взаимодействия игровой логики с физикой и анимациями Unity.

## Условия разработки

Проект разрабатывался в течение одного учебного года и должен был соответствовать заранее утверждённому техническому заданию.

Одной из основных сложностей был масштаб: в ограниченные учебные сроки требовалось реализовать достаточно большое количество игровых механик и контента.

Поэтому при проектировании делался упор на относительно простую архитектуру, в которую можно было добавлять новое оружие, атаки, противников и другие игровые элементы без значительной переработки существующего кода.

## Анализ аналогов

В качестве аналогов рассматривались:

- Cuphead;
- Contra;
- Hollow Knight;
- Don't Starve.

Наиболее близким ориентиром был **Cuphead** как сложная 2D-игра с выраженным акцентом на сражения с боссами и механики run and gun.

Аналоги использовались прежде всего для определения жанровой ниши, предполагаемого уровня сложности и общего направления игрового процесса.

## Технологии

Основной средой разработки был выбран **Unity**, игровая логика реализована на **C#**.

Unity использовался для работы с:

- 2D-физикой;
- игровыми сценами;
- анимациями;
- коллизиями;
- пользовательским вводом;
- игровыми объектами.

Для рисования и редактирования спрайтов использовался **Aseprite**.

В проекте также применялись:

- **Rigidbody2D** — для физического поведения объектов;
- **Collider2D** — для обработки столкновений;
- **PlatformEffector2D** — для односторонних платформ;
- **Unity Input System** — для обработки пользовательского ввода.

## Архитектура

Игра реализована как модульный монолит: приложение поставляется как единый продукт, но внутренняя игровая логика разделена на функциональные части с отдельными зонами ответственности.

В моей части проекта были выделены системы:

- главного героя;
- оружия;
- боссов;
- обычных противников;
- достижений;
- анимированных объектов-атак;
- объектов окружения.

Для взаимодействия между компонентами использовались **UnityEvent**, ссылки на компоненты и публичные интерфейсы классов.

Такой подход позволял достаточно независимо развивать отдельные части игровой логики и добавлять новые типы атак, оружия и противников.

## Система состояний персонажа

Для управления главным героем была реализована система состояний.

Персонаж может находиться в нескольких основных состояниях:

- движение по земле;
- присед;
- нахождение в воздухе.

Каждое состояние наследуется от общего класса и содержит собственную логику:

- входа в состояние;
- выхода из состояния;
- обновления;
- обработки прыжка.

Переключением состояний управляет отдельный менеджер.

Такое разделение позволило не смешивать различные сценарии движения в одном классе и отдельно связывать их с физикой и анимациями персонажа.

## Система оружия

В игре реализовано **пять видов оружия**, различающихся:

- дальностью;
- уроном;
- траекторией атаки;
- областью поражения;
- скоростью атаки.

Дальнобойное оружие работает через создаваемые во время выстрела объекты-снаряды.

Для ближних атак используются временные области поражения.

Направление атаки зависит от действий пользователя и текущего направления персонажа.

## Боссы и система атак

Логика сражений с боссами строится вокруг `AttackManager`.

Он отвечает за:

- последовательность атак;
- выбор текущего поведения босса;
- переключение фаз сражения в зависимости от оставшегося здоровья.

Отдельная атака может включать не только действие самого босса, но и:

- появление дополнительных противников;
- создание объектов-атак;
- активацию элементов окружения.

Для реализации атак используются префабы, анимационные события и динамическое изменение коллайдеров в зависимости от текущей фазы анимации.

Такой подход позволял собирать разные сражения с боссами из отдельных игровых механик.

## Система достижений

Для достижений была реализована событийная система.

Централизованный менеджер получает информацию о событиях игрового процесса и проверяет, выполнены ли условия для открытия конкретных достижений.

Это позволило отделить проверку достижений от основной логики персонажа, противников и других игровых объектов.

## Результат

В рамках моей части проекта была реализована значительная часть основной игровой логики.

В частности:

- передвижение персонажа;
- прыжок;
- присед;
- рывок;
- взаимодействие с односторонними платформами;
- получение урона;
- временная неуязвимость после получения урона;
- восстановление здоровья;
- несколько типов оружия;
- различные модели атак;
- управление поведением и фазами боссов;
- дополнительные противники;
- опасные объекты окружения;
- система достижений.

Игровая логика была связана с анимациями, физикой и системой коллизий Unity, после чего разработанные компоненты были объединены с остальной частью командного проекта.

## Особенности проекта

Проект не ставил целью создание нового игрового жанра или принципиально нового алгоритма.

Основной игровой особенностью стало сочетание классической run and gun-механики с последовательными сражениями с боссами. Каждый босс должен был иметь собственный набор атак, несколько фаз и отличаться от остальных игровой механикой.

С инженерной точки зрения моя часть проекта была построена вокруг нескольких относительно независимых систем:

- конечного автомата состояний персонажа;
- системы оружия;
- менеджера атак и фаз босса;
- событийной системы достижений.
